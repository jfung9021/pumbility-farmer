Current behavior amendment - November 23, 2026 (v6)

The Overall tab now shows expected overall gain against the reconstructed
combined Top 50. This supersedes the calculation-free Overall proposal below.
Singles and Doubles keep independent peer groups, median targets and mode gains.
Overall keeps those targets and evidence, merges the two mode Top 50 histories,
selects the strongest 50 chart contributions and estimates replacement gains.
A chart already in the combined Top 50 replaces itself; another chart replaces
the combined cutoff. Targets with no overall gain are omitted, then rows sort
by expected overall gain. Original mode gain remains available in calculation
details. Unknown results are never filled with zero. Actual Phoenix 2 facts and
official grade/plate estimates follow the existing per-chart merge policy.

The UI uses the existing Recommendations card layout with jackets, chart badges,
compact metadata, mode or overall gain labels and expandable calculation details.
The Overall baseline is inspectable; official standing is shown separately.

Pro Farming: separate mode datasets and consolidated Overall
Implementation plan - November 23, 2026

Status: implemented locally on November 23, 2026. This revision supersedes the
earlier overall-only v2 Pro design. The running v4 engine uses the 50th percentile
and independent Singles/Doubles calculations; Overall consolidates their rows.

1. Requested behavior and gain meaning

Pro Farming should mirror the existing Recommendations interaction with three
mode tabs: Overall, Singles, Doubles. Co-op remains outside Pro chart scope.
Singles recommends only current official S24+ charts; Doubles only D25+ charts.
Keep Phoenix2-only inputs, exact-tag identity matching, and the actual official
OVERALL top-300 eligibility gate. Mode estimates do not create a new top-300 gate.

Construct a Singles dataset and a Doubles dataset independently. Each contains
its mode-specific player Pumbility, Top 50 baseline, peer cohort, chart targets,
and estimated gains. Overall consolidates the resulting recommendation rows.

Default interpretation of "just consolidates": preserve each source row's
mode-specific gain unchanged. Overall sorts those rows but does not calculate
a combined Top 50 gain. Consequently, label these values "Singles gain" and
"Doubles gain", or "Mode Pumbility gain". Do not label the merged values as
official overall Pumbility gains. A mode improvement may not affect the game's
combined Top 50. A clarification about gain labeling was requested; this is the
documented default implemented after the user's instruction to implement this plan.

                      Phoenix2 score facts
                       /                \
           Singles histories         Doubles histories
           Singles Top 50            Doubles Top 50
           Singles cohorts           Doubles cohorts
           S24+ chart q50            D25+ chart q50
           Singles gain rows         Doubles gain rows
                       \                /
                         merge + sort
                             Overall

No independent Overall skill fit, cohort, percentile, target, baseline, gain
calculation, or eligibility decision belongs in the consolidation step. Display
the already-captured official overall rank/Pumbility as profile context. Never
add Singles and Doubles totals to invent an overall Pumbility value.

3. Capture and build the underlying mode datasets

Keep raw captures and identity links private. All sources must be Phoenix2.
Capture the current chart catalog, overall ranking, and unsupplemented official
scores with matching weekly timestamps. The baseline includes ALL current
Singles/Doubles levels; S24+/D25+ applies only to recommendation candidates.

Extend official player-history capture from 300 to all 1,000 players returned by
the current ranking. A player with lower overall Pumbility can have higher
Singles-only or Doubles-only Pumbility than the recipient, so excluding ranks
301-1,000 would distort mode cohorts. Only recipients retain the top-300 gate.
Keep the existing bounded workers and per-player weekly checkpoints. Publish
only after the required peer-history population is captured, or explicitly mark
a partial population and withhold a complete-generation claim. Do not discard
the 700 uncaptured histories as zero or narrow the population silently.

Use readable PIUScores profiles/records where available and retain the official
fallback for every other player. Fetch additional consented personal histories
only for exact-linked accounts used by the chosen peer population. Record source
identity and capture dates for every input. Never substitute private unshared
accounts, supplemented leaderboard rows, Phoenix1 scores, or converted P1 scores.

Create a chart-fact index per official player:
  - Join current chart ID, type, level, and metadata.
  - Keep at most one best result per unique chart.
  - Prefer actual PIUScores Pumbility/plate when its score matches or exceeds the
    captured official score for that chart.
  - Fill missing results, or newer/higher official scores lacking a corresponding
    personal result, using the official raw score and declared plate guess.
    Preserve a known higher actual chart Pumbility as a floor for that chart.
  - Mark whether each retained value is actual or estimated; sources may be
    personal-only, official-only, or mixed.
  - Split this index into Single-only and Double-only histories. A chart from
    one mode must never contribute to the other's total, cutoff, or cohort.

For each player/mode, sum the highest 50 chart Pumbility values and retain the
contributing charts, cutoff, source flags, observed count, and source dates.
At least 50 usable unique observations are required to establish this revision's
mode Top 50 baseline. Fewer observations means the mode is unavailable/insufficient
for rating or gain estimation, not a zero rating or an empty-slot gain.

Remove the current completeness comparison against official overall Pumbility
for mode baselines: a Singles total below the official combined total is normal,
as TUSA demonstrates. Completeness/source decisions instead use the mode's
observed chart facts, actual-versus-estimated provenance and available count.
Do not force either mode's estimate to match the overall total or report their
difference as an error. Label mode Pumbility estimated when derived from guessed
values; there is no verified independent official mode total in the live API.

4. Independent cohort selection

For mode m, the recipient's mode Pumbility is P_m, the sum of its mode Top 50.
Select only other players with usable mode-m ratings, excluding the subject's
official ID and deduplicating duplicate PIUScores account links.

Try inclusive [P_m, P_m+100], then +150 if fewer than ten peers, then +200 if
still fewer than ten. Stop at the first successful window and retain all peers
within it. If +200 remains below ten, retain those peers and add the nearest
lower mode-Pumbility players until ten are selected. Resolve cutoff ties by
deterministic official rank and player ID; overall rank is a tie-breaker, not
the skill metric. If the usable population is still below ten, expose its actual
count and limited support.

Build two different cohorts when the player's mode skills differ. Singles must
not use overall or Doubles Pumbility to select its peers, and vice versa. The
count threshold applies to the player cohort; missing chart scores do not cause
an undocumented second widening per chart. Keep cohort/source-quality metadata
separate for the two modes.

5. Target scores, plates and mode gains

For each mode's eligible charts, use only raw, unsupplemented official scores
from that mode's selected peers, one score per peer/chart. Personal data can
inform actual chart Pumbility baselines; it must not supplement peer target
scores that are absent from the official leaderboard.

Use the linearly interpolated 50th percentile:
  h = (n-1)*0.5
  q50 = sorted_scores[floor(h)] + fractional(h) *
        (sorted_scores[ceil(h)] - sorted_scores[floor(h)])

Keep full precision through plate/grade decisions. Truncate q50 to the minimum
score of its earned Phoenix2 grade; do not round up to another grade.
Retain the fixed plate assumptions applied to raw q50 before grade truncation:
  exactly 1,000,000          PG
  above 995,000, below 1M    SG
  at or below 995,000        MG
Exactly 995,000 remains MG. Show a required score of 1,000,000 for a PG target,
even though the SSS+ grade boundary is 995,000.

Calculate expected chart Pumbility using current type/level and target grade/
plate. Calculate marginal gain against that mode's Top 50:
  - Chart already in mode Top 50: max(0, target value - current chart value).
  - Chart outside the mode Top 50: max(0, target value - mode 50th cutoff).
  - Missing usable mode baseline: no gain estimate; do not fill unknown slots
    with zeros or display full chart Pumbility as improvement.

Retain only positive mode gains. Preserve the raw q50, truncated grade target,
assumed plate, existing chart result/provenance, peer observations/cohort count,
board-cap diagnostics, source mode and mode gain. Sort deterministically by
gain, expected chart Pumbility, song title and chart ID.

6. Overall is a pure consolidation

The only inputs to consolidate_pro_modes are finalized Singles and Doubles
results from the same model/source generation. The function:
  1. Collects all source recommendation rows from ready modes.
  2. Keeps every calculation field unchanged, including q50, grade, plate,
     expected chart value, gain, coverage and baseline provenance.
  3. Rejects accidental repeated chart IDs; different S/D charts of the same
     song remain distinct. Do not silently merge contradictory duplicate rows.
  4. Sorts the union using the same deterministic gain-first sort key.
  5. Applies display limits only after consolidation, retaining full source lists
     for filtering and pagination. Do not merge independently truncated results.

No score, grade, plate, cutoff or gain is recomputed here. Overall displays the
source mode on each row and uses its source gain label. It has no synthetic
combined baseline or third cohort. Mode totals may appear as two reused summary
cards; the captured official overall total may appear separately as context.

If one mode is unavailable, show the available mode unchanged and explain which
mode lacks evidence. A Doubles issue must not block Singles or the combined
view's usable Singles rows. Zero positive gains is a valid ready-mode result,
distinct from unavailable mode data. Do not add hypothetical gains across rows
to promise a total increase; each row represents a separate candidate attempt.
