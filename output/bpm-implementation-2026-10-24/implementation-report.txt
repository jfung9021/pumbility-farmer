Metadata plumbing and compatibility

song_bpm_metadata.py provides exact song+variant resolution, validation and the
shared bucket helper. scripts/build_song_bpm_runtime.py compiles/checks the small
runtime config without network access or dated research-cache dependencies.
npm run bpm:build / bpm:check expose this workflow; backend bundle staging also
rejects a stale compiled catalog.

Current sync/snapshot loading, analyzer and recommendation projections, model
catalogs, Top Scores, combined tier catalog builders and local readers preserve
songType/bpmMin/bpmMax/bpmFocal. New fields remain optional on historical rows.
Snapshot schema stays2 so the change does not trigger a full score refetch.

bpmPolicy=focal-v1 selects the new API semantics. Metadata identity is version1
with revision60a50c007ed1448998fe4bec9006b3a2edf72459a6344e9b2eedd6f3780f40ad.
Personal radar uses method7/profile12; official comparison uses schema3/methodv3.
Legacy contracts remain deliberate. Lazy tier details and caches pin both the
numerical generation and metadata revision. Python signed tier overlays verify
the base hash and produce a matching derived public hash. TypeScript local views
retain the publication as base evidence without claiming a Python signature for
their derived JSON.

scripts/build_bpm_metadata_view.py stages metadata over retained tier artifacts.
bpm_metadata_migration.py / scripts/backfill_song_bpm_metadata.py provide a pinned
metadata-only database dry-run/apply and separate local snapshot staging. Apply
checks the complete active chart roster, source/payload/revision/pointer hashes
under the publication advisory lock and one transaction; it changes only chart
metadata revisions and typed display columns, preserving players/consents/scores.
Prepared artifact pointers can be promoted in that transaction. Full snapshot
import/reconciliation is deliberately not used for this metadata operation.
